# Agent Note: 模型回复输出背景：开关加单一固定颜色

Status: implemented

[English](2026-08-15-output-tint-single-fixed-color.md) | 中文

## 问题

[调色盘决策](../feature/2026-08-14-assistant-output-tint-appearance.md)让开关附带六个预设色块与原生取色器。实际使用后产品方向反转：对一块克制的输出底色而言，选色界面带来的负担大于收益。需求收敛为一个开关加一个默认颜色，克制且与整体页面风格融洽。

## 决策

外观行现在只有开关。开启时持久化 `OUTPUT_TINT_COLOR`（`rgb(237, 243, 254)`，即 `--dsw-static-deepseek-50` 的值，也是用户气泡表面 `--dsw-specific-bubble` 的底色）；关闭时持久化空字符串。`ui-theme.outputTint` 保持字符串形态——空字符串关闭、颜色值开启——因此与 ui-conversation 的快照契约不变：聊天视图仍收到解析后的 CSS 颜色，深色模式下继续用 color-mix 减弱。

调色盘从界面消失，但持久化字段里可能还留着本次改动前写入的调色盘遗留值。采纳时任何非空持久化值都会归一为 `OUTPUT_TINT_COLOR`：之前开着底色的用户仍保持开启、以固定颜色渲染，而不是让运行时携带一个界面已无法表达的颜色。

## 曾考虑的替代方案

- **布尔持久化字段。** 不采用：快照仍需向聊天视图暴露具体的 CSS 颜色，布尔值就得在主题服务内多一步映射——一个开关用两种表示。颜色字符串仍然是诚实的持久化值：它正是聊天视图绘制的内容。
- **把调色盘遗留值归一为空字符串（关闭）。** 不采用：刻意开启过底色的用户会被这次移除静默关闭；以固定颜色保持开启才保留意图。
- **保留调色盘。** 产品决策拒绝：底色是克制的视觉辅助，不是定制化界面。

## 后果

设置行缩成一个开关；色块／取色器样式、调色盘文案与 settings-chrome 快照行一并移除。固定颜色天然在品牌体系内：与用户气泡同款浅品牌色，输出卡片读作同一会话表面的一部分；深色模式仍以 color-mix 减弱到 24%。调色盘遗留的持久化值在采纳时收敛到固定颜色，因此没有过时的自定义颜色能比产出它的功能活得更久。预发布立场让这次收敛成为静默迁移而非兼容垫片：调色盘没有外部消费者。
